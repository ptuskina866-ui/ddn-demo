# Демонстрационная версия Dream Design

Статическая версия публичной части [ddn.by](https://ddn.by/) для согласования структуры и оформления. Проект переносит доступное публичное содержимое в самостоятельный сайт и применяет предложенные изменения: единый изумрудный стиль, блоки направлений, упорядоченный каталог и связь продукции с выполненными мебельными проектами.

**Демонстрация:** [ptuskina866-ui.github.io/ddn-demo](https://ptuskina866-ui.github.io/ddn-demo/).

Фактический состав выгрузки и ошибки источника отражаются в `manifest/report.json` и `dist/data/site.json`. Полноту следует оценивать по этим данным, а не по количеству страниц, показанных на главной.

## Что находится в репозитории

- `dist/` — готовая статическая демонстрация, которую публикует GitHub Pages.
- `dist/data/site.json` — изделия, категории, проекты, информационные страницы и сведения об источнике.
- `dist/assets/source/` — локальные изображения и другие публичные материалы компании.
- `scripts/crawl.py` — повторная выгрузка публичного содержимого и изображений.
- `scripts/verify_site.py` — проверка структуры данных, локальных файлов и ограничений демонстрации.
- `scripts/build_aliases.py` — переходы со старых путей страниц к соответствующим разделам демонстрации.
- `manifest/report.json` — отчёт о полученных материалах и недоступных адресах.
- `.github/workflows/pages.yml` — публикация `dist/` через GitHub Actions.

Сырые ответы исходного сайта в `cache/` служат для повторного запуска выгрузки и не включаются в публикацию.

В выдаче каталога скрываются только точные дубли: должны совпадать название, описания, фотографии, категории и атрибуты. Одинаковое название само по себе не объединяет изделия. Все исходные записи и их прямые адреса сохраняются. В текущем снимке скрыты 5 повторных карточек; 3 записи о пневматике вынесены в справочную часть, поэтому обычная выдача содержит 583 изделия из 591 исходной записи.

## Запуск на компьютере

Нужен Python 3.10 или новее. Для просмотра готового сайта дополнительные пакеты не требуются.

Из папки проекта:

```sh
python -m http.server 4173 --directory dist
```

Откройте [http://localhost:4173/](http://localhost:4173/). Переходы используют адреса с `#`, поэтому работают и в подпапке репозитория на GitHub Pages.

## Проверка

```sh
python scripts/verify_site.py
```

Проверка сообщает количество записей, сверяет ссылки на локальные изображения, ищет забытые внешние обработчики форм, счётчики и признаки случайно включённых секретов. Записи о спортивной пневматике проверяются отдельно: в демонстрации они имеют справочное назначение и не должны содержать коммерческие призывы.

Эта автоматическая проверка дополняет просмотр страниц на компьютере и телефоне.

## Обновление содержимого

Для повторной выгрузки и оптимизации изображений дополнительно нужен Pillow:

```sh
python -m pip install Pillow
```

```sh
python scripts/crawl.py --refresh
python scripts/build_aliases.py
python scripts/verify_site.py
```

После обновления нужно просмотреть отчёт выгрузки и проверить, что изменения источника не повредили страницы и подписи. Флаг `--refresh` заново получает ответы и изображения с исходного сайта; без него используются уже сохранённые ответы из `cache/`. Демонстрация не синхронизируется с WordPress автоматически при каждом посещении.

## Исходные адреса страниц

В демонстрации сохраняются переходы по исходным путям товаров, категорий, проектов и информационных страниц. Например, адрес вида `/ddn-demo/product/исходное-название/` открывает соответствующую страницу каталога. Переходы вычисляют путь к корню относительно своего расположения, поэтому работают и в подпапке репозитория на GitHub Pages.

Старые адреса вида `/catalog/page/2/` также открывают каталог. Номера старых и новых страниц не сопоставляются: размер страницы и порядок выдачи в демонстрации изменены.

Чтобы заново сформировать их после обновления `site.json`, выполните `python scripts/build_aliases.py`. Список переходов записывается в `manifest/aliases.json`. Скрипт не заменяет настоящую главную страницу и другие существующие файлы. Служебные страницы аккаунта и оформления заказа ведут к пояснению демонстрационного режима, а записи о пневматике — в справочный раздел.

В опубликованной копии стоят запрет индексации и `robots.txt` для демонстрации.

## Форма заявки

Форма работает в демонстрационном режиме. Можно выбрать файлы, увидеть их названия и проверить сообщения формы. Заявки не отправляются, а выбранные файлы не загружаются на сервер и не передаются компании.

Для реальной работы понадобятся отдельная серверная обработка, согласованные ограничения файлов, защита загрузок и настройка доставки обращений. GitHub Pages публикует только статический сайт.

## Спортивное направление

Лыжероллеры и справочные сведения о пневматических изделиях отделены от мебельных, школьных и дошкольных материалов. Справочная часть не предназначена для оформления заказа или продвижения оружия. Исходные рекламные тексты, инструкции и коммерческие призывы для этих записей не переносятся в опубликованные данные.

## Публикация на GitHub Pages

1. Разместите проект в репозитории с веткой `main`.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. Отправьте изменения в `main` или запустите workflow **Deploy demonstration to GitHub Pages** вручную.
4. После успешного выполнения ссылка появится в окружении `github-pages` и в настройках Pages.

Workflow проверяет проект и публикует только папку `dist/`. Он использует `actions/checkout@v6`, `actions/configure-pages@v5`, `actions/upload-pages-artifact@v4` и `actions/deploy-pages@v4` по [официальной документации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Материалы компании

Логотип, фотографии и исходные тексты принадлежат их правообладателям и используются в демонстрации изменений для Dream Design. Наличие этих материалов в публичном репозитории не предоставляет лицензию на их дальнейшее использование. Код демонстрации также не имеет отдельно предоставленной открытой лицензии.

Это самостоятельная демонстрационная версия для согласования. Действующий сайт компании и его административная панель не изменяются при просмотре или публикации этой копии.
